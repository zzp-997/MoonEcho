# 回声 — 深夜情绪急救站 产品规划文档

## 一、产品定位

**APP名称**：回声

**一句话定位**：深夜情绪急救站 — 年轻人的情绪出口 + AI朋友

**核心差异**：不是通用AI聊天，是情绪急救。现有AI聊天产品都是"你随便聊什么"，回声做的是"我今晚情绪很烂，我只需要一个地方倒出来"。

**核心用户**：
- 画像A：情绪过载的上班族（22-30岁，一二线城市，白天消耗大量情绪劳动，下班后社交能量耗尽，有情绪想倾倒但找不到安全出口）
- 画像B：社交焦虑的年轻人（18-28岁，想被倾听但面对真人时社交成本过高）

**共同痛点**：想被倾听，但不想面对真人评价。AI朋友天然适合——永远倾听、永不评判、随时在线、不会泄露秘密。

---

## 二、核心规则

1. **社交权限**：陌生人可浏览公开动态，必须双方互加好友才可私聊，禁止陌生人直接骚扰；
2. **发布模式**：每条动态独立选择实名或匿名发布，无全局身份切换；
3. **动态权限**：每条动态可单独设置可见范围（全部公开/仅好友可见/仅自己可见）；
4. **树洞规则**：树洞吐槽区仅支持匿名发布，仅可评论点赞，无法直接发送好友申请；
5. **AI规则**：AI功能覆盖"情绪陪伴+文案辅助+聊天辅助+内容审核"，用户可自主开关；
6. **推荐规则**：不限制注册年龄，AI优先推送年龄相近的动态内容。

## 三、功能模块（6个月范围）

### 核心层——做不好就不上线

| 功能 | 说明 | 验收标准 |
|------|------|---------|
| 注册登录+基础信息 | 手机号/微信登录，填写年龄、城市、职业 | 完成注册到进入首页 < 30秒 |
| AI陪伴好友 | 3种预设性格（温柔倾听/毒舌吐槽/理性开导），多轮对话，基本记忆（记住用户提到的事） | 连续5轮不跑题，对话无明显幻觉 |
| 树洞吐槽区 | 匿名发布+匿名评论，AI生成虚拟昵称和标签，违规内容自动拦截 | 发布到展示 < 3秒 |
| 情绪日记 | 每日记录情绪（标签+文字），AI生成周度情绪报告 | 数据持久化，报告可回看 |
| AI安全审核 | 文本内容审核，过滤低俗/辱骂/广告 | 误杀率 < 5% |
| 通知推送 | AI朋友主动发消息（晚安问候、情绪关怀），互动通知 | 日活用户收到至少1条推送 |

### 增强层——做到及格线

| 功能 | 说明 | 及格线 |
|------|------|--------|
| 动态广场 | 实名/匿名发布图文，AI文案润色 | 能发布、能浏览、能互动 |
| 好友系统 | 申请+双向同意+私聊+基础AI聊天辅助 | 加好友流程通顺，聊天可收发 |
| AI智能画像（基础版） | 基于兴趣标签+行为生成画像 | 生成3-5个标签，可手动修改 |
| 个人中心 | 基础信息展示、动态列表、设置 | 页面完整，设置可保存 |

### 明确不做（6个月内）

- 线下活动、线上实时活动（观影房、歌会等）
- 短视频发布
- 群聊、好友分组
- AI深度匹配/每日推荐算法
- 同城动态区
- AI配图/配乐/滤镜

## 四、开发节奏——两阶段策略

### 核心逻辑

先验证AI情绪陪伴闭环成立，再加社交功能。原因：
1. **冷启动**：AI朋友不需要其他用户，第1个用户进来就有完整体验
2. **价值验证**：先回答"社恐人群真的愿意和AI聊天倾诉吗？"
3. **开发节奏**：AI功能依赖LLM API，前端工作量可控；社交功能复杂度更高
4. **AI催化社交**：AI朋友可主动引导用户去树洞，降低社交门槛

### 阶段一：AI情绪陪伴闭环（Month 1-3）

**Month 1：基础设施 + AI朋友核心**

| 周次 | 任务 | 交付物 |
|------|------|--------|
| W1-W2 | 项目搭建、数据库设计、注册登录、基础信息填写 | 可注册、可登录、可填写信息 |
| W2-W3 | AI朋友对话核心：对接LLM API，多轮对话，prompt设计 | 可和AI朋友聊天 |
| W3-W4 | AI性格系统：3种预设性格，对话记忆（记住最近5轮关键信息） | 切换性格后对话风格明显不同 |

**Month 2：情绪日记 + AI联动**

| 周次 | 任务 | 交付物 |
|------|------|--------|
| W5-W6 | 情绪日记：情绪标签选择+文字记录+日历视图 | 每天可记录，可回看 |
| W6-W7 | AI情绪报告：周度自动生成情绪趋势+AI解读 | 每周一自动生成上周报告 |
| W7-W8 | AI朋友与情绪日记联动：AI主动提及用户最近情绪变化 | AI能说"你最近好像不太开心" |

**Month 3：AI体验打磨 + 阶段一内测**

| 周次 | 任务 | 交付物 |
|------|------|--------|
| W9-W10 | AI朋友主动关怀：晚安问候、情绪低谷时安慰、节日问候 | 每日至少1次主动触达 |
| W10-W11 | 对话质量优化：长对话稳定性、边界case、安全底线 | 连续20轮对话无崩溃/跑题 |
| W11-W12 | 内测版发布：10-20个目标用户内测，收集反馈 | 可安装的测试版 + 反馈问卷 |

**阶段一验证门控：**

| 指标 | 目标 | 意义 |
|------|------|------|
| 7日留存率 | ≥ 30% | AI朋友有足够吸引力 |
| 日均对话轮次 | ≥ 10轮 | 用户真的在聊天，不只是试一下 |
| 情绪日记7日连续记录率 | ≥ 20% | 情绪记录形成习惯 |
| 内测NPS | ≥ 30 | 产品方向被认可 |

> ⚠️ 如果验证失败（7日留存 < 15% 或 NPS < 0）：暂停社交层开发，回到AI体验优化。

---

### 阶段二：社交层叠加（Month 4-6）

**Month 4：树洞吐槽区**

| 周次 | 任务 | 交付物 |
|------|------|--------|
| W13-W14 | 树洞核心：匿名发布+AI生成虚拟昵称/标签+匿名评论 | 可匿名发布、可评论 |
| W14-W15 | AI内容审核：实时审核发布和评论，过滤违规 | 违规内容不展示 |
| W15-W16 | 树洞与AI朋友联动：用户树洞吐槽后，AI主动说"想聊聊吗？" | AI主动关怀触发 |

**Month 5：动态广场 + 好友系统**

| 周次 | 任务 | 交付物 |
|------|------|--------|
| W17-W18 | 日常分享区：图文发布（实名/匿名可选）、AI文案润色、浏览流 | 可发布、可浏览 |
| W18-W19 | 好友系统：好友申请+双向同意+私聊+基础AI聊天辅助 | 好友流程闭环 |
| W19-W20 | 个人中心+AI画像基础版 | 画像可展示 |

**Month 6：打磨 + 公测**

| 周次 | 任务 | 交付物 |
|------|------|--------|
| W21-W22 | 整体体验优化：性能、UI打磨、边界case、推送策略 | 流畅可用的产品 |
| W22-W23 | 公测版发布：100-200人公测，收集数据和反馈 | 公测版本 |
| W23-W24 | Bug修复 + 数据分析 + 产品方向复盘 | 公测报告 + 下阶段规划 |

## 五、技术栈

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 前端框架 | Uni-app + Vue3 + TypeScript | Vue生态，跨端效率高（iOS/Android/H5/小程序），社区成熟 |
| 状态管理 | Pinia | Vue3官方推荐，简洁轻量 |
| UI组件库 | uni-ui + 自定义主题 | 官方维护，稳定性好 |
| 后端框架 | FastAPI + SQLAlchemy 2.0 | 异步原生，WebSocket友好，自动API文档 |
| 数据库 | MySQL 8.0 | 自有服务器部署，成熟稳定，JSON字段支持 |
| 缓存 | Redis | 会话管理、AI上下文缓存、消息队列 |
| 实时通信 | FastAPI WebSocket（需封装ConnectionManager） | 私聊实时通信（阶段二），需自实现心跳/重连/僵尸检测 |
| LLM | 智谱GLM-4-Flash/Plus（主）+ MiniMax abab6.5（备选） | 中文情感理解强，成本低，合规；MiniMax情感场景专优 |
| AI记忆 | Redis（短期）+ MySQL（中期/长期） | 三层记忆架构，MVP不做向量数据库 |
| 图片存储 | 阿里云OSS | 与内容审核一体，CDN加速 |
| 推送 | 极光推送 | 国内到达率95%+，Uni-app插件成熟 |
| 内容审核 | 阿里云内容安全 | 成熟稳定，按量付费 |
| 任务队列 | APScheduler | 轻量单进程，定时任务够用，比Celery减少运维复杂度 |
| 部署 | Docker Compose + Nginx | 自有服务器，一键部署 |
| 监控告警 | Uptime Kuma + 钉钉机器人 | 轻量级监控方案 |

## 六、商业模式

**短期（0-6个月）**：不赚钱，验证留存优先。

**中期（6-18个月）可行路径：**

| 模式 | 可行性 | 预期ARPU | 说明 |
|------|--------|----------|------|
| 订阅制（Pro） | 高 | 15-25元/月 | 免费版限对话次数/天，Pro无限次+情绪报告+AI人设微调 |
| 情绪报告 | 中 | 9.9元/次 | 月度/季度情绪分析报告 |
| AI风格包 | 中 | 6-12元/个 | 不同回应风格AI人设，低开发成本 |

**成本关注**：AI API调用费（智谱GLM-4），单用户月均约0.5元。免费用户日限10次对话可控制成本。

**关键判断**：情绪类产品付费意愿取决于习惯强度，连续21天打开则付费转化显著提升。第一阶段的唯一目标是日活留存。

## 七、冷启动策略

### 种子用户来源

**渠道1：小红书（主战场）**
- "深夜emo""情绪崩溃""社交内耗"话题流量巨大，用户画像高度重合
- 以"情绪日记""深夜树洞"内容形态出现，评论区引导
- 目标：500-1000个种子用户

**渠道2：即刻/V2EX**
- 开发者+互联网人群，对AI产品接受度高
- 发产品开发记录，"一个人用6个月做了一个深夜情绪App"

**渠道3：大学生社群**
- QQ群/微信群，社恐高发群体，群传播效应强
- 以"解压工具"名义推荐，不说"AI聊天"

### 种子内容准备

1. AI人设初始对话样本：20组对话示例，覆盖焦虑/疲惫/孤独/愤怒/迷茫场景
2. App Store描述和截图：传递"深夜emo时的陪伴"
3. 3-5篇小红书种子内容：上架当天发布

## 八、风险与应对

| 风险 | 严重度 | 应对策略 |
|------|--------|---------|
| 冷启动死循环 | 高 | AI朋友不依赖其他用户，第1个用户就有完整体验 |
| 匿名区恶意内容 | 高 | 事后举报+快速响应优先，事前AI拦截为辅，避免误伤真实表达 |
| AI能力不达预期 | 中 | MVP只承诺AI能做到的事，标注"AI辅助"而非暗示"AI搞定" |
| "双向加好友才可私聊"社交阻力 | 中 | 好友申请AI代写打招呼语，AI陪伴填补等待空窗期 |
| AI太好用导致不需要社交 | 中 | AI主动推荐树洞共鸣内容，温和建议"看看其他人怎么应对" |
| 社交产品长验证周期 | 中 | 准备6个月资金和心理预期，前3个月数据不好不代表方向错 |
| 合规风险 | 高 | 使用国产大模型（智谱GLM-4），数据不出境；ICP备案、隐私政策上线前完成 |
| Uni-app流式输出卡顿 | 高 | 测试`onChunkReceived`方案，准备分段显示降级方案 |
| WebSocket不稳定 | 高 | 封装ConnectionManager：心跳(30s)+断线重连(指数退避)+僵尸检测 |
| 大模型情感对话质量不确定 | 中 | 实测GLM-4 vs MiniMax（50场景），准备备选模型 |
| 单机部署瓶颈 | 中 | Uptime Kuma监控+钉钉告警+数据备份（MySQL binlog + Redis AOF） |

**月度成本预估（分阶段）**：

| 项目 | 开发阶段(M1-3) | 测试阶段(M4-6) | 生产阶段(1000 DAU) |
|------|---------------|---------------|-------------------|
| 云服务器（自有） | 0元 | 0元 | ~100-150元 |
| 图片存储 | 0元（本地） | 0元（MinIO） | ~20-50元（OSS） |
| 内容审核 | 0元（Pass） | 0元（本地过滤） | ~300-450元（阿里云） |
| 短信 | 0元（Mock） | 0元（控制台） | ~100元（阿里云） |
| 推送 | 0元（Mock） | 0元（极光免费） | 免费（极光） |
| AI模型 | 0元（Mock） | 0-50元（免费额度） | ~500元（GLM-4） |
| **月合计** | **0元** | **0-50元** | **约1000-1200元** |
